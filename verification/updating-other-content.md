# Updating Other Content 検証記録

## 対象と環境

- 公式例: [htmx Updating Other Content](https://htmx.org/examples/update-other-content/)
- 実装: `/examples/updating-other-content`
- 要件: F-01、F-04〜F-09、F-30
- 環境: Windows x64、Java 25.0.2、Spring Boot 4.1.2、htmx 2.0.11、VS Code 統合ブラウザー (Chrome 150.0.7871.250 / Electron 43.8.3)

## 自動テスト

- `.\mvnw.cmd --batch-mode -Dtest=UpdatingOtherContentTests test` — 成功。13件、失敗0、エラー0。
- `.\mvnw.cmd --batch-mode verify` — 成功。229件、失敗0、エラー0。

MockMvc で全ページ・htmx 部分応答、入力値の保持と HTML エスケープ、CSRF、通常フォームの PRG、セッション分離、20件上限、名前59/60/61文字・メール253/254/255文字、版の欠落・形式不正・過長、古い版による追加・初期化拒否、版不正時の最新一覧と件数の OOB 更新、通常フォームでの競合エラー表示と入力保持を確認しました。

## 実ブラウザー確認

- 有効な連絡先を追加し、一覧の行・件数・通知が一つの応答で更新され、両フォームの版が一致することを確認。
- 不正なメールアドレスで送信し、422後も入力値と既存一覧・件数が保持され、メール欄へフォーカスが移ることを確認。
- 版が欠落した送信は422となり、既存一覧・件数を保ち、最新状態の再読み込みリンクを表示することを確認。
- 追加・初期化の版が不正な422応答では、対応する再読み込みリンクへフォーカスが移ることを確認。
- 古いタブで版不正の422が返る場合も、最新一覧と件数が一致して更新され、追加フォームの再読み込みリンクへフォーカスすることを確認。
- 一方のタブで追加した後、もう一方の古いタブから送信すると409となり、一覧を変更せずエラー通知を表示することを確認。
- 古いタブの連絡先フォームをブラウザーの通常フォーム送信で送ると、409の全ページ応答に最新一覧・入力値・このサンプルの再読み込みリンクが表示されることを確認。
- メールを修正して再送信し、件数が更新され、追加ボタンへフォーカスが戻ることを確認。
- 初期化後、一覧が空になり、件数が0に戻り、完了通知が表示され、初期化ボタンへフォーカスが戻ることを確認。
- ブラウザー JavaScript の実行例外は観測しませんでした。422と409は意図した応答であり、ブラウザーのコンソールにはHTTPエラー応答が記録されます。

## 未確認事項

- JavaScript を完全に無効化した実ブラウザー操作。通常フォーム送信経路は実ブラウザーで確認し、成功・入力エラー・CSRF は MockMvc でも確認しました。
- 競合するタブから古い版を送るケースは実ブラウザーで確認しました。通信遅延による応答順の入れ替わりを実ネットワーク上で再現する確認は未実施です。
- 実ネットワークの切断・タイムアウト、別ブラウザー、スクリーンリーダー、ハイコントラスト。

## 公式例との差分

公式例の更新範囲拡大・OOB・イベント発火の考え方を解説し、実装では一覧とフォームを含むパネルを主差し替えし、件数と通知を OOB 差し替えします。イベント発火後に別 GET を行う方式は採用せず、応答内で表示をそろえます。入力検証・CSRF・セッション分離・版による競合拒否・件数上限・通常フォームを加えています。追加依存はありません。
