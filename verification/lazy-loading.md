## 実ブラウザー

VS Code統合ブラウザーとPlaywrightで確認。一時サーバー18080を使用し、確認後に停止済み。遅延・HTTPエラー・通信断はブラウザーの要求制御で模擬し、アプリに故障用パラメーターや待機処理を追加していない。

| 操作 | 結果 |
| --- | --- |
| 初回の集計要求を600ms遅延 | 初期説明・未取得表示を先に表示、処理中表示とaria-busy=true |
| 自動要求中に手動リンクをクリック | 集計要求は1件だけ。固定6・12・4件の表を表示し、busy解除。リンクのフォーカスを保持 |
| 取得完了後に待機 | 表は1個、追加の自動取得なし |
| 初回集計を503にする | 未取得表示を残し共通エラー通知、busy解除。手動再取得で表を表示 |
| 取得後に接続失敗を模擬 | 前回の集計HTMLを保持し通信失敗通知、busy解除 |
| timeoutをブラウザー内だけ100msにして要求を遅延 | 前回表示を保持、集計用タイムアウト・手動再試行案内、busy解除。通常設定10秒に戻し回復 |
| 集計URLに直接アクセス | 表示要求1件、集計入り全体ページ、自動取得loadなし |
| htmxと共通JSの読み込みを遮断 | 初期ページは未取得、通常リンクで集計入りページへ移動。完全なJavaScript無効とは区別 |
