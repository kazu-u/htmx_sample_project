## ブラウザー確認

VS Code 統合ブラウザー（Chromium）と Playwright 操作、検証専用ポート18080で確認。要求中断を伴う競合は、POST応答を600ms遅らせる一時的なローカルHTTPプロキシ（18081）でも確認した。プロキシは検証補助のみでアプリや依存には追加しない。

| 操作 | 結果 |
| --- | --- |
| メール欄へ不正形式を入力し Tab で離れる | POST `/email` のパラメーターはメールのみ。422の結果だけを差し替え、入力DOMと値を保持し、フォーカスは移動しない。`aria-invalid=true` を反映 |
| 名前は空のままメールを有効形式へ変更し Tab | 200の有効結果。名前は検証しない。入力中は以前の結果を消して再検証を案内 |
| 名前空欄のまま全体送信 | 422のフォーム全体を表示。メールを保持し、名前へフォーカス |
| 名前を修正して全体送信 | 200、登録・メール送信はしていない旨を表示し、成功通知へフォーカス。名前の再入力でも古い成功通知を消す |
| XHR送信を600ms遅延し、要求後にメールを変更 | 古い422結果も古い200結果も差し替えなし。新入力と再検証案内を保持。別値へ変更して元の値へ戻す操作でも古い結果を反映しない |
| 単独検証中にメールを再変更し、再び欄を離れる | プロキシ経由で旧要求が中断（XHR status0）され、最新要求だけが結果を表示（200/422の両方を確認）。要求2件・差し替え1件、busy解除。最新値の検証を取りこぼさない |
| 遅延した単独検証中に全体送信 | プロキシ経由で単独要求を中断して全体送信を優先。全体フォームだけを更新し、新しい結果を古い単独結果が上書きしない |
| 遅延した全体送信中にsubmit・changeイベントを追加 | プロキシ経由で二重送信なし、全体要求の中断なし。送信中は名前・メール・送信ボタンが無効、`aria-busy=true`。終了時は操作可能となりbusyを解除 |
| メール欄からEnterキーで全体送信 | プロキシ経由でも全項目成功。メールを保持し成功通知へフォーカス、busy解除 |
| CSRF metaを不正値にし、単独要求後に入力を変更 | 実際の403を共通通知。古い応答の抑止処理で403を隠さない |
| 検証URLだけを接続失敗にして送信 | 通信エラー通知、入力保持、busy解除。接続を戻して入力を変更すると再検証成功 |
| 検証URLを300ms遅延し、ブラウザー内だけtimeoutを100msに短縮 | 検証のタイムアウトと再試行案内を通知し入力保持。ページ再取得後の再検証成功。通常設定は10秒のまま |
| compositionstart/input(isComposing)/compositionendを合成 | 要求0件、changeを明示してから1件。実OSの日本語IME操作を確認したとは扱わない |
| 390px幅・動きを減らす設定 | 横スクロールなし（viewport390 / scrollWidth375）。ラベル・通知・ボタンの配置と`aria-live=polite`を確認 |
| 初期状態に戻すリンク | GETで空のフォームに戻る。業務状態は変更しない |
| 既存4サンプルの回帰確認 | Click to Edit・Edit Row の422/修正保存/フォーカス、Click to Load の3件追加、Delete Row の1行削除と隣接ボタンへのフォーカスが動作 |

最終確認でJavaScriptの未処理例外・CSP違反・意図しない外部要求は検出なし。意図した422/403/通信断/タイムアウト/要求中断に伴うブラウザー・htmxのエラーログは発生する。XHRのsend自体を遅らせる方法では、送信前中断が実際の通信中断と異なるため、中断の検証証拠には用いない。
