## ブラウザー確認

アプリを `http://127.0.0.1:8083/examples/dialogs-custom` で起動して確認しました。

- 「案内をダイアログで開く」で同一オリジンの GET が送られ、取得断片が表示されてネイティブなモーダルダイアログが開くことを確認しました。
- ダイアログを開くと閉じるボタンへフォーカスが移り、閉じるボタンまたは Escape で閉じると起動ボタンにフォーカスが戻ることを確認しました。
- 375px 幅でページの横はみ出しがなく、ダイアログ全体が表示領域に収まることを確認しました。
- ブラウザーの要求を 503 応答に置き換えて、HTTP エラー通知が表示され、ダイアログが開かないことを確認しました。これはサーバー障害を実際に発生させた検証ではありません。
- `/examples/dialogs-custom/detail` を通常の GET で開くと全体ページが返り、案内とサンプルへ戻るリンクが表示されることを確認しました。1440px 幅では本文が中央に収まる単列表示になり、横はみ出しがありません。
- 通常の成功フローで CSP 違反や意図しない外部リクエストは観測しませんでした。失敗応答のシミュレーションではブラウザーに 503 のコンソール記録が出ます。

## セキュリティ・状態・未確認事項

- `HX-Request` は応答形式の選択にだけ使い、CSRF・認可・検証の省略条件にはしません。取得は GET のみで、状態変更・保存はありません。
- 表示内容は固定の架空案内です。HTML 断片にスクリプトを含めず、同一オリジンで配信する外部 JavaScript と CSS のみを使います。
- `showModal()` で標準モーダル動作とフォーカス移動を使います。Escape は外部 JavaScript が閉じる操作に結び、閉じた後は記録した起動要素にフォーカスを戻します。
- **未確認:** JavaScript を実際に無効化したブラウザー環境。通常アクセスで代替ページを表示できることと `noscript` リンクの出力は確認しましたが、JavaScript 無効化状態での操作そのものは試していません。
- **未確認:** 別ブラウザーでのネイティブ `<dialog>` の挙動、実ネットワークでの遅延・切断、実際のサーバー障害。

## 公式例との差分

[htmx 公式 Dialogs - Custom](https://htmx.org/examples/modal-custom/) は独自オーバーレイと Hyperscript を使います。この例では依存追加と独自フォーカス管理を避けるため、標準 `<dialog>` と外部 JavaScript を使い、htmx の差し替え完了後にモーダルを開きます。閉じる操作・Escape・フォーカス復帰、JavaScript 無効時のページ代替、エラー通知、日本語解説を加えています。
