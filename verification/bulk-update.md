## 実ブラウザー

VS Code統合ブラウザーとPlaywright操作で、ポート18080の一時サーバーを使用。正式なEdge / Chromeのバージョン検証とは区別する。
検証用の遅延・エラーはブラウザーの要求制御で模擬し、アプリや依存への追加はしていない。

| 操作 | 結果 |
| --- | --- |
| 特定行だけ有効にして保存 | 200、全4行の保存済み状態・チェック・版が一致、保存ボタンへフォーカス、busy解除 |
| 全選択して3回連続保存 | すべて200、全員有効。変更後は過去の成功通知が消え、未保存の案内 |
| 全解除して保存 | 200、全員無効。選択なしをエラー扱いしない |
| 不正ID 5を混ぜて保存、修正して再送信 | 422、保存済み状態は不変、既知ID 2の選択保持、エラーへフォーカス。再送信200 |
| 送信前を600ms遅延し、続けてrequestSubmit | 入力・両ボタンを無効化、aria-busy=true、POSTは1件のみ。200後busy解除 |
| 同じセッションの別要求で先に保存後、古いフォームを送信 | 409、古い画面の選択・版を保持し再読み込みを案内 |
| CSRFヘッダーのトークンを不正にする | 403とCSRF・再読み込み案内 |
| 503を模擬 | 選択・保存済み状態を保持し共通通知、busy解除。要求制御解除後200 |
| 接続失敗を模擬 | 選択を保持し通信失敗通知、busy解除 |
| timeoutをブラウザー内だけ100msにし要求を遅延 | 選択保持、保存結果不明・再取得案内、busy解除。通常設定10秒へ戻し回復200 |
| htmxと共通JSを遮断して通常フォームで保存・初期化 | POSTとリダイレクトで指定行のみ有効、その後初期値の1・3へ復帰。完全なJavaScript無効化とは区別 |
| 390px幅、reduced-motion | viewport390 / scrollWidth375、横スクロールなし |
| チェック欄でSpace、Tab、保存ボタンでEnter | チェック切替・次の欄への移動・200保存、保存ボタンへフォーカス復帰 |

遅延応答の最初の試行でブラウザー側の取得・応答転送が完了せずタイムアウトした。サーバー側の保存は完了していたため再読み込みで確認し、送信前の遅延方式に変更して二重送信を再検証した。
完全なJavaScript無効の別ブラウザーコンテキスト作成は統合ブラウザーの制約で失敗し、スクリプト遮断による代替確認に切り替えた。
意図した422・403・409・503、通信失敗・タイムアウト・スクリプト遮断に伴うブラウザー/htmxログは発生する。正常保存の確認では未処理JavaScript例外は検出しなかった。
