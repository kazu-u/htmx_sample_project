## 実ブラウザー

VS Code統合ブラウザーとPlaywrightで `http://127.0.0.1:8080/examples/progress-bar` を確認した。ブラウザーエンジン・バージョンはツールから取得できず、個別のEdge / Chromeのバージョン確認とは区別する。

| 操作 | 結果 |
| --- | --- |
| 初期表示 | 操作領域は1つ。初期状態は0%、ポーリングなし |
| 成功する処理 | 進捗0%から20%、100%へ更新。完了後は`hx-trigger`がなくなり、開始ボタンへ戻る |
| 失敗する処理 | 10秒後に失敗状態・100%を表示。ポーリング停止、開始ボタンを表示 |
| キーボードで開始・キャンセル | Enterで開始後にキャンセルボタンへ、キャンセル後に開始ボタンへフォーカスが移動 |
| 進捗更新中のフォーカス | 完了応答待ち中に Tab で手動取得リンクへ移動し、完了後もそのフォーカスを保持 |
| 実行中にキャンセル | キャンセル状態になり、ポーリングを停止 |
| 開始要求と手動取得の競合 | 開始応答保留中は開始ボタン2つを無効化し、手動取得リンクを利用不可にする。手動GETは送信されず、開始POSTも中断されない |
| 手動進捗GETがHTTP 500 | 進捗表示を保持して自動取得を停止。2.1秒間に追加ポーリングなし。手動再試行で停止状態を解除 |
| 実行中の手動取得 | 状態参照に加えてキャンセル操作もOOB更新で復元 |
| 完了後の古いキャンセル | 409を返し、共通エラー通知を表示 |

これらの追加ブラウザー確認では、開始応答保留とHTTP 500をPlaywrightで模擬した。通信失敗試験では、意図したHTTPエラーおよびブラウザー/htmxの通信ログが出る。
