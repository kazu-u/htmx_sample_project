## 自動テスト

MockMvc で Security・MVC・Thymeleaf を通すテストと、同時更新の状態テストを含む。

- ページ全体 / HTML 断片、ローカル静的リソース、CSP・キャッシュ抑制
- 編集・保存・キャンセル・初期化、通常フォームのリダイレクト
- 入力エラー時の422、値保持、状態非更新
- 名前の0 / 1 / 59 / 60 / 61文字、メールの253 / 254 / 255文字と不正形式
- 保存・初期化で CSRF トークンなし / 不正の403、および有効トークン付き成功
- レンダリングされた通常フォームの hidden トークンを取り出し、テスト支援のトークン注入なしで保存・初期化に成功
- セッション分離、古い版の409、同時に同じ版を更新した場合に一方だけ成功
- 古い版と不正入力が重なった要求は409を優先し、現在の保存値を変更しない
- revision の36文字不一致は409、37文字と空白は422となり、422断片の `revision-error` 属性と保存値不変を確認
- 403 / 404 / 409 のエラーページ文言と、セッション上限到達時の503・復旧案内
- 利用者入力のエスケープ、必須パラメーター欠落、更新 URL への GET 拒否
- 実際に描画された htmx の設定値（評価・スクリプト無効、同一オリジン、10秒タイムアウト等）
- 実 Tomcat で20分のセッション設定、100セッション成功・101個目の503拒否、満杯時に失効セッションの CSRF 更新要求も503、パラメーター20個受理・21個400拒否、フォーム16KB受理・1バイト超過413拒否

Mockito の動的 Java エージェントに関する JDK 警告が出る。テスト成功とは区別し、将来の JDK 更新時はテストランナーの設定を再確認する。

## 実ブラウザーでの確認

統合ブラウザーの操作ツールで確認した。アプリにブラウザーテスト用の依存は追加していない。

| 項目 | 結果・方法 |
| --- | --- |
| 部分更新 | 編集→422→保存でもページ見出しの DOM が同じで、連絡先だけが置き換わる |
| フォーカス | 編集開始で名前、422で不正な入力欄、保存後で編集ボタンへ移動 |
| 入力保持 | 422で不正メールが残り、修正・保存できる |
| 版エラーのフォーカス | revision だけが不正な422でエラー説明へフォーカスし、共通通知にも同じ説明を表示。フォーカス先は `revision-error` |
| 503通知 | ブラウザーで `htmx:responseError` の503イベントを発火し、復旧案内が表示されることを確認。HTTP応答そのものは実Tomcatテストで検証 |
| キャンセル・初期化 | 未保存値を破棄し、保存済み表示へ戻る。初期化で架空の初期値へ戻る |
| 競合 | ブラウザーの同一セッション内で別要求による更新後、元フォームの保存が実サーバーから409。入力が残り案内が出る |
| 403・404・500の UI | ブラウザーの応答差し替えでエラーを模擬し、通知・入力保持を確認。さらに CSRF ヘッダーを不正値にし、実サーバーの403と中立的な案内文を確認 |
| 通信断・復帰 | ブラウザーの要求中断で通信断を模擬。入力を残し、通信復帰後に保存できる |
| タイムアウト | 応答を停止して通知・入力保持を確認。短縮した100msの設定でも分岐を確認。通常設定は10秒 |
| 処理中 | 応答待ちの間、保存ボタン無効・`aria-busy`・インジケーターを確認 |
| 標準フォーム | アプリと htmx のスクリプトを取得不可にし、htmx 未ロードで編集・保存・リダイレクト・初期化を確認。保存と初期化の成功通知も表示される |
| キーボード | 編集ボタンの Enter 操作と、差し替え後の入力フォーカスを確認 |
| 小画面 | 幅390pxで横方向のはみ出しがないことを確認 |
| CSP | 通常操作・検証エラーで `securitypolicyviolation` なし。正常操作で予期しない JavaScript 例外なし |

最初の確認で、キャンセルリンクからの要求時に相対 `hx-disabled-elt` がボタンを見つけられない問題を検出し、明示的な `#contact button` へ修正した。
その後の編集・キャンセル・初期化でセレクター警告が再発しないことを確認した。
HTTP エラーの試験時に出るブラウザー / htmx のエラーログは、意図したエラー注入と区別して確認する。

## 配布物の検証

- Temurin ZIP は Adoptium API の SHA-256 と照合。
- Maven ZIP は公式 SHA-512 と照合し、計算した SHA-256 を Wrapper に設定。
- 別の空キャッシュで Wrapper の新規ダウンロードと `--version` を確認。
- htmx はタグ付き公式配布物のハッシュ・ライセンスを同梱。

## 未確認・制約

- Edge / Chrome の独立インストール、Firefox、Safari、実機モバイル、スクリーンリーダーでの操作
- OS の JavaScript 無効設定そのもの（スクリプト取得失敗の代替経路は確認）
- 20分を実際に待つセッション失効、長時間の負荷・大量アクセス（セッション総数の境界は実 HTTP で確認）
- 遅延要求の成功完了と重複要求数のブラウザー計測はツール側の遅延転送が完了せず未確認。同時版更新の整合性はサーバーテストで検証
- JavaScript のイベント回帰を自動化するブラウザー依存は、初期依存を抑える方針から追加しない。既存の実ブラウザー手動確認を継続し、サーバー側のエラーページ・競合順序・セッション容量は自動テストで検証する
- Copilot / Local の新規チャットでの共通指示自動添付と、開発セッションの承認 UI
- Linux CI の結果は GitHub 上の実行後に PR で報告する。ローカルの Windows 成功から推定しない

未確認を確認済みとは扱わない。ローカル学習用の最初の例であり、本番公開の認証・認可・運用対策を提供するものではない。
