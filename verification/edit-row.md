## ブラウザー確認

- 複数行を編集用 tr に切り替えても、入力・ラベル・エラーの ID が重複しない。
- 1行の保存後も別行の未保存入力が残り、保存済みの行だけ表示用 tr に戻る。編集ボタンへフォーカスが戻る。
- 名前空欄・メール不正で422の行を差し替え、入力を保持する。settle 後、最初の不正入力にフォーカスする。修正後は正常に保存できる。
- キャンセルで保存せず元の行に戻り、その行の編集ボタンへフォーカスが戻る。
- 同じ行への先行保存を別要求で行い、古い編集からの保存で409を通知し、未保存の入力を画面に残す。
- 同じ行の二重送信を含めて2行の保存を連続発行した。ブラウザー内で XHR の送信を500ms/1500ms遅らせ、実際に送られた要求が2件のみで、片方の完了時も `aria-busy` と処理中通知を維持することを確認。両方成功後に busy 状態とボタン無効化が解ける。
- 存在しない ID への htmx 要求で404通知を表示し、編集行を残す。不正 CSRF トークンによる保存は403通知となり入力を残す。
- 390px 幅で編集行がページの横スクロールを発生させず、入力に対応するラベルが存在する。
- 正常な並行操作中の JavaScript 例外・CSP 違反は0件。異常系の422・404・409・403の HTTP エラーログは意図どおりの拒否であり、JavaScript 例外とは区別する。

ブラウザー上の一時的な送信遅延・ID・トークン改変は検証のためだけに使い、アプリのソースには含めていない。
