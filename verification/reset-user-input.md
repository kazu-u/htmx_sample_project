## ブラウザー確認

アプリを `http://127.0.0.1:8081/examples/reset-user-input` で起動して確認しました。

- 有効なメモを送信すると、200応答で一覧の先頭に追加され、入力欄が空になった。
- 121文字の入力は422となり、入力値を保持した。エラー文、`aria-invalid="true"`、入力欄へのフォーカスを確認した。
- 入力を修正して再送信すると、メモが追加され、入力値と以前のエラーがクリアされた。
- キーボードで送信した場合、応答後も送信ボタンにフォーカスが戻ることを確認した。
- HTTP 500の応答では入力値が残り、共通エラー通知が表示された。
- POST通信を中断した場合も入力値が残り、通信失敗の通知が表示された。
- キーボードで送信した際、無効化中にフォーカスを失っても成功・HTTP 500後に送信ボタンへ戻る。422では修正用の入力欄へフォーカスすることを確認した。
- 幅375pxで横方向のはみ出しがない。ページJavaScriptの実行エラーはなかった。

## 通常フォーム・状態・制約

- MockMvc で通常フォームの成功時にページ全体と空のフォームが返り、今回のメモだけが表示されることを確認した。
- MockMvc で通常フォームの422時に入力値を保持し、Thymeleafでエスケープすることを確認した。
- CSRFトークンなしのPOSTが403となることを確認した。
- メモはサーバー状態に保存せず、htmxでは現在表示中のDOMにのみ追加する。再読み込みで消えることをMockMvcで確認した。

JavaScript無効状態でのブラウザー操作、別ブラウザー、実ネットワーク上の通信断は未確認です。通常フォームはサーバーテストで応答内容を確認しています。
