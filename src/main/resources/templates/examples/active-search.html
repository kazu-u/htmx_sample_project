仕組みと通信

検索は参照のみで、業務状態を変更しません
操作メソッド / URL応答と差し替え先
初期表示・通常フォーム・条件の初期化GET /examples/active-search?query=検索語200・ページ全体。query省略・空欄は全件
入力後500ms待機・Enter・検索ボタン同じGET200・#search-results全体。0件も正常応答
60文字を超える検索語同じGET422・検索結果の代わりに項目別エラー。通常要求は全体ページ
  • ActiveSearchController が固定8件を部分一致検索し、Thymeleaf がHTMLを返します。SearchForm は前後空白を除く前の文字列長（JavaのUTF-16）を60までに制限します。
  • hx-get は送信先、hx-target="#search-results" と hx-swap="outerHTML" は結果領域だけの置換です。入力は差し替えずフォーカス・カーソルを維持します。
  • active-search.js が input と composition イベントを扱い、変換終了後500msで独自イベントを送ります。Enter・ボタンの送信では待機タイマーを解除し、変換中の送信は抑止します。
  • hx-trigger="submit, active-search" は通常送信と独自イベント、hx-sync="this:replace" は進行中の検索を最新検索で置き換えます。送信前に入力が変わった場合も旧200/422応答は反映しません。
  • 検索中も入力・ボタンは有効です。hx-indicator と aria-busy が通信中を示し、結果が古い間は案内を表示します。共通app.jsが422・HTTPエラー・通信失敗を処理します。

異常系と復帰

開発者ツールでmaxlengthを外し61文字送ると422です。入力とエラーを保持し、修正して再検索できます。通信断・10秒のタイムアウト・503などは共通通知し、入力と直前の結果を残します。接続を戻し「検索する」で同じ条件でも再試行できます。

状態・制約と安全性

業務状態や検索履歴はサーバーに保存しません。GETの検索語はURL・ブラウザー履歴・アクセスログ等に残り得るので、個人情報や秘密情報を入力しないでください。CSRF用セッションは既存構成（無通信20分・全体100個）に従います。検索は参照のみのGETなのでCSRFトークンを送らず、更新操作の保護は変更しません。

検索は名前・チーム・メールのいずれかに一致する単一の文字列で、複数語のAND検索・全角半角やかなの同一視・ページ分割・DB・外部APIは扱いません。サーバーが初期結果を表示するため、初回表示のための追加通信も不要です。

公式例との差分・出典

htmx公式 Active Search の入力待機と結果更新を参考に独自実装しました。公式例のPOST・イベント条件式・load取得ではなく、GET・外部JavaScriptでのIME制御・サーバーでの初期表示を採用し、安全設定allowEval:falseを維持しています。追加依存はありません。
