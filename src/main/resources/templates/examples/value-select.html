Spring Boot + htmx サンプル

連動する選択肢

都道府県を選ぶと、その都道府県に属する市区町村だけを取得して候補を入れ替えます。

  1. 都道府県を選び、市区町村の候補が更新されることを確認します。
  2. 別の都道府県に変えると、市区町村の選択が初期状態に戻ります。
  3. 市区町村まで選んで「選択結果を確認する」を押します。

仕組みと通信

固定データを参照し、サーバー状態は変更しません
操作メソッド / URL応答と差し替え先
初期表示GET /examples/value-select200・ページ全体。両方とも未選択
都道府県の変更・解除GET /examples/value-select/cities?prefectureId=ID200・市区町村欄を置換し、前の選択結果をクリア
JavaScript 無効時の候補表示GET /examples/value-select?action=loadCities&prefectureId=ID200・ページ全体。親を保持して子候補を表示
結果の確認GET /examples/value-select?action=confirm&prefectureId=ID&cityId=ID200・選択結果だけを置換。通常フォームではページ全体
存在しない ID・親子不一致同上422・エラーを表示。子の値は未選択に戻す
  • hx-get と hx-target="#city-field" は選択変更時の取得先と差し替え範囲です。親セレクト自体は置換せず、フォーカスを保ちます。
  • 送信ボタン名を伴わないフォーム送信も、htmx では選択結果の確認として検証します。
  • 候補はサーバーが固定データから作ります。最終確認でも子 ID がその親に属するか検証し、画面の値だけを信用しません。
  • 状態はURLに送る選択値だけで、サーバーやセッションに保存しません。データはすべて架空です。

異常系と復帰

開発者ツールで候補にない親・子 ID を送ると422で拒否します。正しい親は保持し、子は選び直せる初期状態へ戻します。通信断・HTTPエラー・10秒のタイムアウトでは共通通知を表示し、親の選択を残して再操作できます。

制約と安全性

この例は固定の架空データ3組だけで、登録・永続化・外部API・DBは使いません。全通信は参照のみのGETです。候補と親子関係はサーバー側で検証し、HTMLへの値出力はThymeleafでエスケープします。

公式例との差分・出典

htmx公式 Value Select の親セレクトから子候補を取得する構成を参考にしました。自動車メーカー・車種ではなく架空の地域を使い、選択解除時のリセット、結果の明示確認、親子関係の検証、通常フォームの代替を追加しています。公式例の外部ロゴ等は使わず、追加依存はありません。
