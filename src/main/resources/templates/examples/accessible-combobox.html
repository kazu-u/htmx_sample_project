候補から担当者を選択

名前または部署を入力し、サーバーから返る候補をキーボードやポインターで選びます。候補以外の文字列は送信できません。

  1. 「佐藤」「企画」などを入力し、300ms後に候補が表示されることを確認します。
  2. 下矢印・上矢印で候補を移動し、Enterで選択します。Escapeで候補を閉じます。
  3. 「選択を確定する」を押し、サーバーが候補IDを照合した結果を確認します。

  • role="combobox" と aria-controls / aria-expanded / aria-activedescendant は外部JavaScriptが候補領域の状態に合わせて設定します。
  • 入力欄は候補名を含む表示用テキスト、hiddenのIDは選択済みの値です。文字を編集するとIDを消し、候補を選び直すまで送信できません。
  • JavaScript 無効時は同じGETフォームで候補を絞り、通常のselectから選びます。選択結果もサーバーで確認します。
  • 固定12件から名前・部署を部分一致検索し、1応答あたり10件まで返します。DB・外部API・セッション保存はありません。

異常系と復帰

開発者ツールで61文字の検索語や存在しない候補IDを送ると422です。入力値を残し、正しい検索語や候補で再送信できます。通信断・HTTPエラー・10秒のタイムアウトでは共通通知を表示し、現在の入力を保って再試行できます。

アクセシビリティと制約

矢印キーで候補を移動し、Enterで候補を選びます。Escapeは候補を閉じ、Tabは通常のフォーカス移動を行います。IME変換中は要求せず、応答が古い候補一覧を置き換えないようにします。候補・選択状態・エラーは読み上げ可能な状態で通知します。

自由入力、複数選択、ページ分割、永続化は扱いません。候補検索のGETには検索語がURL・履歴・アクセスログ等に残り得るため、架空データ以外を入力しないでください。

公式例との差分・出典

htmx公式 Active Search の入力待機と Value Select のサーバー描画候補を参考に、検索結果一覧ではなく単一候補の選択に焦点を当てます。WAI-ARIA Authoring Practices の Combobox Pattern を参考にキーボード操作とARIA状態を構成し、追加依存は使いません。
