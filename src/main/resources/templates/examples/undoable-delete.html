取り消せる削除

削除をすぐ確定せず、30秒間の「削除待ち」を設けて、その間に操作を取り消す方法を学びます。

  1. 作業の「削除待ちにする」を押すと、セッション内の状態が削除待ちになります。
  2. 30秒以内なら同じ行の「取り消す」で元に戻せます。
  3. 期限後は削除済みとして扱います。「一覧を再取得」で期限後の表示を確認できます。

仕組みと通信

削除待ちは30秒の期限付き状態です。期限内の取り消し POST だけが状態を戻し、期限後は再取得時に削除済みと表示します。GET は保存状態を変更せず、期限と状態から表示を計算します。

期限切れ・古い版の操作や初期化POST /examples/undoable-delete/{id}/undo または /reset409・状態は変更せず、再取得を案内
  • 削除・取り消し・初期化は CSRF 保護された POST です。通常フォームでも操作でき、JavaScript 無効時の削除確認はサーバー側で検証します。
  • 各行の更新と一覧の初期化に版を含め、二重送信や古い画面の削除・取り消し・初期化は409で拒否します。一覧版は行の版と期限から導出した表示状態を含む同期スナップショットです。存在しない ID は404です。
  • htmx は行だけを差し替え、更新後は操作ボタンへフォーカスを戻します。エラー時は行を保ち、通知を表示します。
  • 期限はサーバーの時計で判定し、期限切れ状態は表示上確定します。GETでは状態を書き換えません。5件固定のため記録数は増えず、明示リセットまたは20分のセッション失効で初期化されます。
  • 期限の境界は30秒ちょうどで取り消し不可です。画面を開いたまま期限が過ぎても、サーバーが取り消しを拒否します。一覧を再取得すると「削除済み」に更新されます。

異常系と状態の寿命

  • CSRF トークンがない・一致しない要求は403、期限切れ・二重操作・古い版は409、存在しない ID は404です。
  • 通信断・タイムアウトでは成功したと決めつけず、通知を確認して一覧を再取得してください。
  • 状態はセッション単位で分離され、20分の無通信またはサーバー再起動で消えます。初期化はそのセッションだけに反映します。

公式例との差分・出典

htmx 公式 Delete Row の行単位更新を参考に、削除の即時確定ではなく期限付きの削除待ちと取り消しを加えています。

固定データ、状態版、CSRF、通常フォーム代替、期限切れの論理確定、セッション分離を実装しています。DB、外部 API、バックグラウンドジョブ、追加依存は使いません。
