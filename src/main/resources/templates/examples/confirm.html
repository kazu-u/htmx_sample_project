Confirm（独自の確認手順）

hx-confirm の確認画面を、外部ライブラリを使わず標準の <dialog> に置き換えます。

  1. 「確認して結果を取得」を選び、独自の確認ダイアログが開くことを確認します。
  2. 「続ける」を選ぶと GET が送られ、結果欄だけが更新されます。
  3. もう一度試し、「やめる」または Escape で閉じると GET が送られないことを確認します。

  • htmx:confirm で hx-confirm の質問を受け取り、preventDefault() で htmx の既定確認と要求を保留します。続ける操作から issueRequest(true) を呼び、既定の window.confirm() を重ねずに要求を送ります。
  • この例の GET は固定の結果を返すだけで、業務状態は変更・保存しません。HX-Request は応答形式の選択だけに使い、Vary: HX-Request を付けます。
  • 標準の <dialog> がモーダル表示を行います。キャンセル・Escape では保留中の要求を破棄し、閉じた後は起動ボタンへフォーカスを戻します。
  • JavaScript 無効時には通常リンクから同じ GET にアクセスできます。第三者 UI ライブラリ、インラインイベント、htmx の条件式は使いません。

異常系と制約

キャンセル時はサーバーへアクセスしません。通信に失敗した場合は共通通知が表示され、既存の結果を保ったままボタンから再試行できます。標準ダイアログの見た目・フォーカス動作はブラウザーに依存します。

公式例との差分・出典

htmx 公式 Confirm は SweetAlert2 とインライン JavaScript を使った例を示します。本サンプルは依存追加を避け、標準 <dialog> と外部 JavaScript の htmx:confirm イベントで同じ要求保留・再開を説明します。確認後の処理は固定 GET に限定し、JavaScript 無効時の通常リンクとエラー通知を加えています。
