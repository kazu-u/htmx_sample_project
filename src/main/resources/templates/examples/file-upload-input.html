フォームエラー後のファイル選択保持

サーバーが422の入力エラーを返してフォームを差し替えても、選択したファイルを再選択せずに修正・再送信できることを確認します。

  1. タイトルを空欄のまま、UTF-8 の .txt ファイルを選択して送信します。
  2. タイトルのエラーを確認し、ファイル選択が残っている状態でタイトルを入力します。
  3. 再送信し、成功通知の後にタイトルとファイル選択が初期化されることを確認します。

送信内容を確認しています…

送信フォーム

ファイル名は120文字以内。内容は検証後も画面に表示せず、保存しません。

仕組みと通信

ファイルは要求処理中だけ一時的に受信し、アプリケーションの状態には保存しません
操作メソッド / URL応答と差し替え
初期表示GET /examples/file-upload-input200・ページ全体
送信POST /examples/file-upload-input200・htmx はフォーム断片を差し替えて入力を初期化。通常フォームはリダイレクト後にページ全体
タイトルやファイルの検証エラー同上422・htmx はエラー付きフォームを差し替え、`hx-preserve` のファイル選択を維持。通常フォームは全体再表示のため選択が失われる
サイズ超過同上413・htmx は共通通知を表示し元フォームを維持。通常フォームは共通エラーページ
CSRF 不正・通信失敗同上403・HTTPエラー・通信断を通知
  • hx-target="#file-upload-input-form" と hx-swap="outerHTML" はフォーム全体をサーバーの入力値・エラー付き断片で置き換えます。422もHTML断片を差し替えるよう共通処理で明示します。
  • hx-preserve はファイル入力だけに付け、入力欄に安定した id を指定します。フォームやエラー表示領域に付けると、修正内容や新しいエラーまで古い要素で置き換わるため、保持対象を入力欄に限定します。
  • 成功時は新しいフォームを表示し、外部 JavaScript がブラウザーのファイル入力を空にします。エラー時はファイルを保持し、タイトルなど通常の入力値と項目別エラーも再表示します。
  • CSRF トークンは通常フォームの hidden 値と、共通 JavaScript が付ける同一オリジン用ヘッダーで検証します。送信中は二重送信を抑止し、エラー項目または成功通知へフォーカスを移します。
  • 別の方法として、ファイル入力を差し替え対象の外に置き、HTML の form 属性でフォームに関連付けられます。この例では公式例に沿って hx-preserve を使います。

異常系と制約

タイトルを空欄または61文字以上にして送信すると422です。エラーを直してもファイルを選び直す必要はありません。拡張子・ファイル名・UTF-8内容が不正な場合も422で、ファイル入力の保持を続けるため、ファイル選択ダイアログから別のファイルに置き換えてください。

1 MiBを超える要求は413です。htmx では共通通知を表示して元のフォームを差し替えず、選択を維持します。通常フォームは共通エラーページへ遷移するため、選択が失われます。これは422のフォーム差し替え時に hx-preserve で選択を保つ動作とは別です。CSRF 不正・通信断・30秒のタイムアウトも成功扱いにしません。JavaScript 無効時の通常フォームはページ全体を再表示するため、選択済みファイルの復元はブラウザーのセキュリティ制約上できません。

受け付けるのは UTF-8 の .txt 1件、1 MiBまで、ファイル名120文字以内です。タイトルは要求中に検証し、状態保存・プレビュー・実行・恒久保存はしません。内容は画面に表示せず、要求終了後にサーブレットの一時データを破棄します。

公式例との差分・出典

htmx 公式 Preserving File Inputs after Form Errors の、ファイル入力に一意の id と hx-preserve を付ける方法を使います。公式例に対して、CSRF、サーバー側のタイトル・ファイル検証、422・413、通常フォームの制約、成功時の選択解除、日本語の説明を加えています。ファイルを差し替え領域の外に置く代替案も説明します。追加依存はありません。
