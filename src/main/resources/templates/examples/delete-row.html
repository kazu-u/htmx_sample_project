仕組みと通信

htmx は削除対象 ID へ DELETE を送り、サーバーは状態を削除した後、空の200応答を返します。空の応答と hx-swap="outerHTML" の組み合わせで、対象行が取り除かれます。

  • hx-delete は更新要求、親の hx-confirm はブラウザー確認、hx-target="closest tr" と hx-swap="outerHTML" は行単位の差し替えを指定します。
  • 通常フォームは POST を使い、Spring Security の CSRF トークンと、JavaScript 無効時の確認チェックをサーバー側で検証します。GET では削除しません。
  • 通常フォーム用の CSRF hidden 項目は htmx の DELETE パラメーターから除外し、共有 JavaScript がトークンをヘッダーだけに付けます。通信中は削除ボタンを無効にし、並行要求がある間は一覧の処理中状態を保ちます。
  • 応答がエラーなら行を残し、利用者へ通知します。成功して行が消えた後は、隣の行か一覧見出しへフォーカスを移します。
  • 削除はセッション内で同期して行い、存在しない ID は404です。別セッションの一覧には影響しません。
  • JavaScript が有効な場合に確認ダイアログを使います。htmx は同一オリジンだけに要求し、断片内スクリプトと式評価は無効です。

異常系と状態の寿命

  • 開発者ツールで ID を存在しない値に変えると404となり、一覧は変化しません。
  • CSRF トークンのない更新は403です。通信断・タイムアウトでは成功したと決めつけず、通知を確認して一覧を再取得してください。
  • 状態はセッション単位の4件から始まり、削除・初期化はそのセッションだけに反映します。20分の無通信またはサーバー再起動で初期状態に戻ります。

公式例との差分・出典

htmx 公式 Delete Row の hx-delete、確認、行ターゲット、空応答という考え方を参考に、Spring MVC / Thymeleaf で独自実装しています。

公式例に CSRF、セッション分離、通常フォーム用 POST と確認欄、初期化、異常応答、キーボードフォーカスの復帰を加えました。アニメーションや追加ライブラリは使用しません。
