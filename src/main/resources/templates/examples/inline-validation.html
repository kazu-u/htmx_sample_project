  • hx-trigger="change" は値を変更して欄を離れたときの検証です。入力のたびには送らないため、日本語 IME の変換途中に要求しません。
  • hx-params="email" は名前等を送らずメールだけを送ります。CSRF トークンは共通 JavaScript がヘッダーに付けます。通常フォームは hidden のトークンを送ります。
  • 単独検証では入力要素を差し替えず、フォーカスも移動しません。入力が変わった後に届く古い検証結果は反映しません。入力し直すと旧結果を消し、再検証が必要なことを表示します。
  • hx-sync="closest form:abort" により全体送信を優先して単独検証を中断します。単独検証中の再変更では、共通 JavaScript が change の処理前に旧要求を中断して最新の検証を送ります。全体送信中は入力・ボタンを無効にし、hx-sync="this:drop" で二重送信を抑止します。
  • ValidationForm はメール単独・全体で同じメール制約を使い、InlineValidationController はどちらもサーバーで検証します。単独検証の成功を送信の許可証にはしません。app.js は CSRF・古い応答の抑止・422・通知を扱います。

異常系と操作性

名前は必須・60文字、メールは必須・形式検証・254文字が上限です（Java の文字列長）。不正なら422と入力・項目別エラーを返します。全体送信の422では最初の不正入力へ、全項目成功では成功通知へフォーカスを移します。

CSRF の欠落・不一致は403、要求上限超過は400・413、セッション上限は503です。通信断・10秒のタイムアウトも通知し、入力を残します。通信を戻して欄を変更するか、全体送信で再試行できます。

状態の寿命と制約

登録・DB保存・メール送信・重複メールの照会は行いません。名前・メールと検証結果は画面と処理中の要求だけにあり、サーバーの業務状態として保持しません。初期化や再読み込みで空のフォームに戻ります。入力には架空データだけを使ってください。

CSRF用のセッションは無通信20分で失効し、全体で100個までです。失効時は入力を必要なら控えて再読み込みしてください。フォーム16KB・パラメーター20個を上限とするローカル学習用です。本番の会員登録やメールの存在・到達性を確認する仕組みではありません。

公式例との差分・出典

htmx 公式 Inline Validation を参考に、Spring MVC / Thymeleaf で独自実装しています。公式例の入力欄ごとの置換と固定の受付メールではなく、結果だけの差し替えと入力形式の検証を採用しました。

CSRF、422、送信時の全項目再検証、古い応答の抑止、通常フォーム代替、日本語解説を加えました。追加ライブラリやインライン JavaScript は使いません。
