  • hx-target="#contacts-panel" が主な更新先です。応答内の hx-swap-oob はパネルの外にある件数と通知を、それぞれの ID を持つ領域へ別に適用します。
  • 外部 JavaScript は成功応答の後だけ入力を初期化し、422・HTTP エラー・通信失敗では入力を保持します。通信中は追加・初期化を無効にし、同じ領域の重複要求を抑止します。
  • 別案として、ページの更新範囲をさらに広げて件数や通知までまとめて置換すれば OOB は不要です。代わりに応答 HTML が広くなり、フォーカスを保持する対象も増えます。
  • イベント発火方式では、POST 成功後にイベントを発火し、一覧が別の GET で再取得します。取得リクエストが増えるため、この例では一つの応答で整合して更新できる OOB を選びます。
  • 通常フォームでも追加・初期化ができ、成功後は PRG でページ全体を表示します。CSRF を維持し、Thymeleaf が入力値をエスケープします。
  • 追加・初期化のたびにフォームの版を更新します。同じセッションの別タブから古い版で送信すると409になり、上書きや追加を拒否します。htmx では入力を保持して通知し、JavaScript 無効時は最新一覧と入力値を含むページを表示します。入力版が欠落・不正な場合は422で再読み込みリンクを表示します。遅れて届いた古い応答も、表示中の版より古ければ JavaScript が差し替えを止めます。

状態・異常系と制約

架空の連絡先は HTTP セッションごとに分離され、最大20件です。再起動またはセッション失効で消えます。初期化すると現在のセッションだけが空になります。データベース保存・外部送信は行いません。

名前は必須・60文字以内、メールアドレスは必須・形式検証・254文字以内です。上限到達時は422で追加を拒否します。CSRF エラー、古い版の409、その他の HTTP エラー、通信断・10秒のタイムアウトでは成功と見なさず、一覧と入力を成功後の状態にしません。

公式例との差分・出典

htmx 公式 Updating Other Content の複数領域を更新する課題を使い、主領域の差し替えに加えて hx-swap-oob で件数と通知を更新します。公式の「更新範囲を広げる」「OOB」「イベント発火」の考え方を解説で比較し、外部拡張なしの OOB を実装します。入力検証・CSRF・セッション分離・上限・通常フォームを追加しています。
