まとめて有効・無効を更新

全4人の有効・無効を、チェック状態どおり一度に保存します。チェックを外した人は無効になります。

  1. 有効にしたい人にチェックを付け、無効にしたい人は外します。
  2. 「全行を保存する」を押します。全解除で全員無効、全選択で全員有効になります。
  3. 「初期状態に戻す」で保存済みの状態と未保存の選択を初期化できます。

仕組みと通信

HTML のチェックボックスは、チェックされた値だけを送ります。Controller が入力を検証し、State が全行を一つの排他区間で保存します。JSON や外部 API は使いません。

ページ全体とフォーム領域の差し替え
操作メソッド / URL応答・差し替え
表示・再取得GET /examples/bulk-update200・通常は全体、htmx は bulk-panel 断片
全行保存POST /examples/bulk-update200・bulk-panel 置換。通常フォームは一覧へリダイレクト
不正ID・重複・版情報の入力不正同上422・全行未更新、既知の行のチェックを保持
古い版同上409・差し替えず選択を保持、再読み込みを案内
初期化POST /examples/bulk-update/reset版照合後、一覧へリダイレクト。古い版は409
  • hx-post は全行の選択と版を送信、hx-target と hx-swap="outerHTML" はフォーム領域の置換を指定します。
  • hx-sync="this:drop" と hx-disabled-elt で二重送信・送信中の変更を抑止します。成功後は保存ボタンへ、422はエラーへフォーカスを移します。
  • フォームの hidden と共通 JavaScript のヘッダーで CSRF トークンを送り、Spring Security が検証します。GET では有効・無効を変更しません。
  • 不正 ID・4件超過・重複は422で全件拒否します。全解除はエラーではありません。入力不正のIDを新しいチェック欄として表示しません。

異常系・状態の寿命・制約

  • 別タブで先に保存してから古い画面で保存すると409です。選択を控え、再読み込みして選び直してください。
  • 開発者ツールでIDを不正な値に変えると422です。CSRF の欠落・不一致は403です。
  • 通信断・タイムアウトは入力を残して通知します。保存結果が不明な場合は成功と推測せず、選択を控えて再読み込みしてください。
  • 架空の4件をセッション単位で分離します。20分の無通信・再起動で初期状態に戻ります。全体100セッションの上限があります。
  • 実際のアカウント・認証・通知は扱いません。本番では対象への認可やデータベースのトランザクションが別途必要です。

公式例との差分・出典

htmx 公式 Bulk Update の、表をフォームで囲みチェック状態を一括送信する考え方を参考に独自実装しています。

公式例は通知だけを差し替えます。本例は保存済み状態と新しい版情報を一致させるためフォーム領域を置換します。通知は output で示し、消えるトーストやアニメーションは使いません。CSRF、入力検証、セッション分離、競合拒否、初期化、通常フォーム代替を追加しました。追加依存はありません。
