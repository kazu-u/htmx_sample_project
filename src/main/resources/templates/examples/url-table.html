仕組みと通信

サーバーは URL の条件から一覧を絞り込み・並べ替えし、該当ページを HTML で描画します。部分応答でも条件フォームを含む一覧領域を返すため、表示と URL の状態が同期します。

読み取り専用の注文データ。各 GET は状態を変更しません。

範囲外のページ番号同じ GET404・対象ページなし。現在の htmx 表示を保ち通知
  • hx-get と通常の href / GET フォームは同じ URL を使います。htmx のリンクには hx-push-url="true" を付け、操作ごとの条件をブラウザー履歴へ追加します。
  • 戻る・進むで htmx が送る履歴復元ヘッダーを Controller が判別し、履歴キャッシュを使わない設定でも全ページを返します。応答形式の違いは Vary に含めます。
  • 絞り込みと並べ替えはページを1へ戻し、既存の他条件は保持します。ページ移動は全条件を引き継ぎます。検索語は60文字以内、1ページ5件、データは固定30件です。
  • URL に検索語が残るため、個人情報・秘密情報を入力しないでください。条件やデータはサーバー・セッションに保存しません。CSRF 用セッションは共通構成に従います。
  • HTML の値は Thymeleaf がエスケープします。htmx は同一オリジンに限定し、スクリプトタグと式評価は無効です。追加依存はありません。

異常系と制約

検索語を61文字にして送ると422となり、入力とエラーを維持します。配送状態・ソート条件・ページ番号をURL上で不正な値にすると、検証エラーまたは404を返します。タイムアウト・通信切断などでは共通通知を出し、条件と表示中の一覧を維持して、同じ操作から再試行できます。

データは架空の会社名を使った固定30件で、DB・外部 API・更新機能・複数語検索・ページサイズ変更は扱いません。GET のため CSRF トークンは送信せず、更新操作の保護設定は変更しません。

公式例との差分・出典

htmx 公式 Examples の取得・差し替えを参考に、Spring MVC / Thymeleaf で独自実装しています。単純な検索結果更新ではなく、絞り込み・ソート・ページングの全状態を URL から再現できること、通常遷移と htmx 履歴を同期することを主題にしています。追加依存はありません。
