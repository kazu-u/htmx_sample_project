ダッシュボード部品の定期更新

架空の注文・在庫カードを5秒ごとに別々のGETで取得します。データは時刻から作る学習用の値で、実在の業務情報ではありません。

  1. 各カードの「今すぐ更新」で、他方のカードを変えずに更新できることを確認します。
  2. 「自動更新を一時停止する」「自動更新を再開する」で定期取得を制御します。
  3. 開発者ツールでカードの要求を失敗させ、直前の値と取得時刻が残り、自動取得が止まることを確認します。接続を戻してカードを手動更新すると復帰します。
  4. タブを非表示にして要求が止まり、表示に戻すと最新値を取得することを確認します。

自動更新の制御

表示中に5秒ごとに取得します。自動更新は表示中の累計5分で終了します。

一時停止中・上限到達後・通信失敗後も、各カードの手動更新は利用できます。

仕組みと通信

2つのカードはそれぞれ独立して取得します
操作メソッド / URL応答と差し替え先
初期表示GET /examples/dashboard200・2カードを含むページ全体
注文カードの自動・手動更新GET /examples/dashboard/summary/ordershtmx は注文カードの値だけを差し替え。通常アクセスは全体ページ
在庫カードの自動・手動更新GET /examples/dashboard/summary/inventoryhtmx は在庫カードの値だけを差し替え。通常アクセスは全体ページ
一時停止・再開ブラウザー内で制御。再開時は各カードにGET停止中は要求なし。再開すると正常な2カードを直ちに個別取得
HTTPエラー・通信断・タイムアウト該当カードのGET値と取得時刻を保持し、カード単位で自動取得を止めて通知。手動更新で復帰
  • hx-trigger="every 5s" は各カードに置き、差し替え対象は値を含む内側の領域だけです。ポーリングを設定した外枠や初回取得トリガーを応答に含めないため、入れ子や再帰的な取得は起きません。
  • hx-sync="closest [data-dashboard-card]:drop" により、同じカードの自動・手動要求が重なったときは後続要求を捨てます。もう一方のカードは独立して取得できます。
  • 外部 JavaScript が表示中の累計時間を計り、5分で自動取得を止めます。非表示タブでは要求を抑止し、表示に戻ると各カードを再取得します。手動のリンクは上限後も使えます。
  • 通信エラー後は失敗したカードだけ自動取得を停止します。前回値と最終成功時刻を残し、手動更新が成功すれば上限時間内で自動取得も再開します。エラー時に連続で自動再試行はしません。
  • 注文数・在庫数・状態は30秒単位の時刻から算出し、GETの回数やセッション状態で変化しません。取得時刻はサーバーのローカル時刻です。
  • 個別取得は必要なカードだけを更新でき、一方の失敗が他方へ波及しません。その代わり要求数はカード数に応じて増えます。一括取得なら要求を減らし同じ時点の値を返しやすくなりますが、不要なデータも送り、失敗が複数カードへ影響します。

状態・異常系・制約

固定の計算式から作る架空データです。DB、外部 API、セッション保存、バックグラウンド処理はありません。GET は参照のみで、時刻が進むことで表示値が変わる場合があります。

自動更新はページが表示されている間だけ時間を計り、利用者の一時停止中と非表示タブでは停止します。表示中の累計5分に達すると自動では再開しません。カード単位の手動更新は引き続き利用できます。

htmx のタイムアウトは10秒です。通信断・HTTPエラー・タイムアウトでは最後に成功した値を保ち、該当カードの自動取得を止めます。接続を戻し、カードの手動更新で復帰してください。JavaScript 無効時は自動取得できません。

公式例との差分・出典

htmx 公式 hx-trigger のポーリング説明を参考に、複数カードを独立して取得する例を作っています。公式の基本例に対して、自動更新の上限・一時停止・非表示タブ制御・手動更新・失敗からの復帰・読み上げ頻度への配慮を追加しました。追加依存はありません。
