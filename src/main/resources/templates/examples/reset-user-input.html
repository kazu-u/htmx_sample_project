送信成功後に入力を初期化

メモの送信が成功した場合だけ、外部 JavaScript からフォームの reset() を呼び、次の入力に備えます。

  1. メモを入力して「追加」を押し、一覧への追加と入力欄の初期化を確認します。
  2. 空欄または121文字以上で送信し、422のエラーと入力値の保持を確認します。
  3. 入力を修正して再送信し、成功応答後にだけ欄が空になることを確認します。

  • hx-target="#note-list" と hx-swap="afterbegin" は成功したメモを一覧の先頭に追加します。422応答は hx-swap-oob でエラー欄だけを置換するため、入力フォームと一覧を壊しません。
  • 外部 JavaScript は htmx:afterRequest のHTTP 2xx応答だけで form.reset() を呼びます。共通処理が422断片を差し替え可能にするため、htmxの successful フラグではなくHTTPステータスを確認し、422・その他の失敗では値を残します。インラインスクリプトや hx-on は使いません。
  • 通常フォームでは htmx の差し替えを行わず、成功後にサーバーが空のフォームを含むページを返します。
  • フォームは CSRF 保護された POST です。送信中は二重送信を抑え、422時は入力欄へフォーカスします。送信中に無効化された操作へフォーカスが落ちた場合は、成功・その他の失敗の後に元の操作へ戻します。Thymeleaf がメモをエスケープして表示します。

異常系と制約

空欄または121文字以上のメモは422で拒否されます。120文字の境界は有効です。文字数はJavaの文字列長で検証します。入力は保持され、修正後に再送信できます。403・HTTPエラー・通信断・10秒のタイムアウトでは成功と見なさず、フォームの内容を消去しません。

メモは固定データにもサーバー状態にも保存しません。htmx で追加したメモは現在のページ上に表示され、再読み込みで消えます。通常フォームの成功応答では今回のメモだけをページに表示します。実際の保存・共有・機密情報の送信は行わない学習用例です。

公式例との差分・出典

htmx 公式 Reset User Input の「成功時だけ入力を初期化する」考え方を使います。公式例の hx-on::after-request によるインライン処理は、CSP と htmx の安全設定に合わせて外部 JavaScript のイベントリスナーに置き換え、サーバー側の入力検証・422・CSRF・通常フォーム・日本語解説を加えています。追加依存はありません。
