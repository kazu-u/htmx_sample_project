仕組みと通信

初期画面と集計の要求は別です
操作メソッド / URL応答・差し替え
初期画面GET /examples/lazy-loading200・説明と未取得表示を含む全体ページ
自動取得・手動再取得GET /examples/lazy-loading/summary200・htmx は集計断片で lazy-content の中身を置換
通常リンク・直接アクセス同上200・集計入り全体ページ。追加の自動取得なし
HTTPエラー・通信断・タイムアウト同上成功と扱わず通知し、未取得表示または前回の集計を保持
  • hx-trigger="load" は外枠の初期処理時に1回発火します。断片には load を含めず、定期取得や再帰的な要求を作りません。
  • hx-target="#lazy-content" と hx-swap="innerHTML" でリンクと見出しを残します。自動取得でフォーカスを奪わず、手動取得でもリンクを保持します。
  • hx-sync="#lazy-panel:drop" で自動・手動取得を同期し、処理中の追加要求を捨てます。リンクは a 要素なので disabled による操作抑止には頼りません。
  • hx-indicator は処理中表示、共通 JavaScript は busy・完了通知・HTTPエラー・通信失敗・タイムアウトを扱います。10秒でタイムアウトし、無限再試行しません。
  • Controller は固定3件を Model に渡し、Thymeleaf がHTMLを生成します。棒は標準の meter 要素で、同じ件数を数値でも表示します。

状態・異常系・制約

  • 固定3件・各0〜20件の架空データです。GETは参照だけで、呼び出し回数により件数を増やしません。DB・外部API・ジョブ・待機処理は使いません。
  • 集計の業務状態はセッションに保存しません。初期URLを再読み込みすると未取得表示から始めます。集計URLへの直接アクセスは取得済み表示です。
  • 共通CSRF用セッションは無通信20分、全体100個の上限です。この例の操作はGETのみですが、他の更新要求のCSRF保護は維持します。
  • 開発者ツールで集計URLを遮断・低速化すると、通知・前回表示の保持・再取得を試せます。サーバー側で意図的に遅くするパラメーターは用意しません。
  • 初期HTMLを軽くできますが、総通信回数は増えます。本番の重い計算の高速化やバックグラウンド処理を実現する例ではありません。

公式例との差分・出典

htmx 公式 Lazy Loading の初期表示後に内容をGETで取得する考え方を参考に独自実装しています。

画像のグラフとフェードの代わりに、架空の集計表と標準 meter を使います。手動再試行、通常リンク代替、競合する取得の抑止、エラー・フォーカスの扱い、日本語説明を追加しました。アニメーション・追加依存はありません。
