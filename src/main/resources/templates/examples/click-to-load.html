仕組みと通信

Controller はページ番号に応じた HTML を返します。htmx は JSON を組み立てず、返された行と次の読み込み操作で現在の操作行を置き換えます。

ページ番号は1始まり。htmx利用時の更新先は #load-more
操作メソッド / URL応答
初期表示GET /examples/click-to-load200・ページ全体、最初の3行
続きを読むGET /examples/click-to-load?page=2 など200・次の行と次の操作行。最後は操作行なし
範囲外ページGET /examples/click-to-load?page=0 など404・対象なし
  • hx-get は次のページを取得し、hx-target="#load-more" と hx-swap="outerHTML" は操作行を新しい行と次の操作行に置き換えます。
  • hx-sync="this:drop" と送信中のボタン無効化で、連続操作による重複取得を抑えます。サーバーはページ数を上限で検証します。
  • 取得は副作用のない GET です。サンプルの状態は持たず、データはサーバー内の固定リストです。
  • 通常フォームでも操作できます。htmx がない場合は次ページまでの一覧全体を再表示し、読み込んだ行を維持します。
  • htmx通信は同一オリジンのみ、HTML内スクリプトと式評価は無効です。CSRF・CSP・エラー通知は既存サンプルと同じ設定です。

異常系と制約

  • URLのページ番号を0や最終ページより大きい値にすると404になります。数値でない値は400になります。
  • 通信失敗・タイムアウトは通知し、既存の行を維持します。再読み込みすれば続きを再取得できます。
  • 担当者は8件、1回に3件の固定データです。DBや外部APIは使わず、セッションにも保存しません。

公式例との差分・出典

htmx 公式 Click To Load の行を次の行に置き換える考え方を参考に、Spring MVC / Thymeleaf で独自実装しています。操作中の行をターゲットとして使い続けるので、差し替えのたびに次の操作要素が新しくなります。

公式例のテーブル更新に加え、CSRF・範囲検証・重複要求対策・終端・通常フォームの代替・日本語の通信説明を用意しました。追加ライブラリやJavaScript式は使いません。
