差し替え時のアニメーション

サーバーから返る同じ ID の要素を CSS transition で見せ、htmx の差し替えと CSS を組み合わせる方法を確認します。

  1. 色のボタンを押し、カードが選んだ色に切り替わると同時に、新しいカードがフェードインする様子を確認します。
  2. 通信中表示、要求中のボタン抑止、要求後も選択ボタンにフォーカスが戻ることを確認します。
  3. OS の「視差効果を減らす」設定を有効にして、動きが短縮されることを確認します。

仕組みと通信

固定の表示候補を GET で取得します。サーバー状態は変更しません。
操作メソッド / URL応答・差し替え

ID がない同上400・要求を拒否
存在しない色 ID同上404・共通エラー通知。カードを置き換えない
通信断・HTTP エラー・タイムアウト同上現在のカードを保ち、共通通知で再操作を案内
  • hx-get は選んだ固定候補を取得し、hx-target と hx-swap="outerHTML" はカードだけを置き換えます。通常の GET フォームも同じ操作の代替です。
  • カードの id を応答前後で同じに保ち、settle 時に htmx-added クラスが外れることで、新しいカードを opacity の CSS transition でフェードインします。色と背景色は新しい要素にすぐ適用され、この例では旧表示から色を補間しません。
  • 要求中はインジケーターを表示し、フォームのボタンを無効にします。差し替え後にフォーカスが失われた場合は、操作元の選択ボタンへ戻します。
  • CSS の prefers-reduced-motion は動きを減らす設定を尊重し、transition をほぼ即時にします。アニメーションは内容理解や操作の条件にしません。

状態・制約

3種類の固定された架空表示だけを使います。GET は参照のみで、データベース・セッション状態・外部 API・追加依存はありません。View Transitions API や htmx 拡張も使いません。

公式例との差分・出典

htmx 公式 Animations の同じ ID を維持する CSS transition と htmx の swap / settle クラスを参考にしています。色を選んでサーバーHTMLを取得する短い例に絞り、動きを減らす設定、通常フォーム、処理中表示、エラー通知を加えています。公式例にある View Transitions API と class-tools 拡張は採用していません。
