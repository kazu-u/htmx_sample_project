Web Components（Shadow DOM）

カスタム要素の Shadow DOM 内にあるボタンから htmx を呼び出し、部品ごとに結果を差し替えます。

  1. 「情報を取得」を押し、押したカードの結果だけが更新されることを確認します。
  2. 同じ操作を別のカードでも試し、各部品の表示が独立していることを確認します。
  3. JavaScript が使えない場合は、各カードの通常リンクから同じ固定データをページ全体で表示します。

HTTP エラー・通信断・タイムアウト同じ URLカード内にエラーを通知し、直前の結果を維持
  • connectedCallback でテンプレートから Shadow DOM を作り、URL を固定候補から設定した後に htmx.process(shadowRoot) を呼びます。初期ページの通常の走査は Shadow DOM の内部までは行わないためです。
  • hx-target="next .summary-result" は押したボタンと同じ Shadow DOM 内で対象を探します。別カードや文書全体を指す global: セレクターは使いません。
  • Shadow DOM は HTML・CSS の適用範囲を分けます。htmx のイベントは外側にも伝わるため、カード自身の状態表示を行い、共通画面用の通知処理とは重複させません。
  • サーバーは固定データを返すだけです。GET による状態変更、DB、外部 API、追加依存はありません。応答は Thymeleaf でエスケープします。
  • カードのスタイルは外部 CSS を Shadow DOM 内から読み込みます。CSP と htmx の selfRequestsOnly / allowScriptTags / allowEval の安全設定は共通設定のままです。

異常系と制約

不明なカード URL は 404 です。HTTP エラー・通信断・10 秒のタイムアウト時は既存結果を残してカード内に通知し、ボタンから再試行できます。JavaScript 無効時も通常リンクで結果ページを開けます。

公式例との差分・出典

htmx 公式 Web Components は Shadow DOM に対する htmx.process と内部セレクターを示します。本サンプルは固定の複数カード、開いた Shadow DOM、通常ページ代替、失敗通知を加えます。開いた Shadow DOM は学習時に構造を確認しやすくするためで、秘密情報の保護境界ではありません。
