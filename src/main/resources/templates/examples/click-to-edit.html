仕組みと通信

Controller が操作を受け付け、Thymeleaf が HTML を生成します。htmx は JSON を組み立てず、返された HTML で連絡先の領域を置き換えます。

すべて /examples/click-to-edit 配下。htmx 使用時の更新先は #contact
操作メソッド / URL応答
初期表示GET /examples/click-to-edit200・ページ全体
編集GET /contact/edit200・フォーム断片
保存POST /contact200・表示断片。不正入力は422・フォーム断片
キャンセルGET /contact200・保存済みの表示断片
初期化POST /reset200・初期表示断片

通常フォームの保存・初期化は成功後にページへリダイレクトします。不正入力は422でページ全体を返します。

  • hx-get / hx-post は送信先、hx-target="this" は更新先、hx-swap="outerHTML" は領域ごとの置換です。
  • hx-sync="this:drop" は同じ領域の通信中に重複要求を捨てます。サーバーも版を照合し、別タブの古い保存・初期化を409で拒否します。
  • 版が古い要求は入力エラーの有無より先に409で拒否します。revision が空欄・36文字超過などの入力制約に反する場合は422になり、制約内でも現在の版と一致しない場合は409になります。
  • ContactState はセッション単位の状態、ContactForm は入力制約、ClickToEditController は通信と表示の選択、app.js は CSRF・エラー・フォーカスを担当します。

異常系の試し方

  • 名前を空欄、メールを不正形式にして保存すると422になります。名前は Java の文字列長で60、メールは254を上限とします。
  • 同じブラウザーの別タブで編集画面を開き、一方を保存してから他方を保存すると409です。入力は画面に残るので必要なら控え、再読み込みして編集し直します。
  • 開発者ツールでオフラインにして操作すると通信エラーです。通信を戻して再試行できます。応答が10秒を超えるとタイムアウトします。
  • CSRF トークンがない・一致しない更新は403です。再読み込みしてから操作してください。存在しない URL は404です。

状態の寿命と制約

データは架空の1件だけ。DB・外部 API は使いません。別ブラウザーとは分離し、同じセッションのタブは共有します。20分の無通信またはサーバー再起動で消えます。開いた画面の値が自動で初期表示へ変わるわけではありません。

認証なしのローカル学習用です。外部公開には認証・認可・HTTPS・負荷対策が必要です。フォームの送信内容は16KBまで（超過は413）、パラメーター数は20まで（超過は400）に制限し、ファイル送信は無効です。

サーバー全体のセッションは100個までです。上限に達して新しいセッションを作れない場合は503になります。既存の画面・セッションを使い、空きがない場合は20分の失効を待つか、ローカルサーバーを再起動してください。
