ブラウザー標準ダイアログ

hx-confirm は送信前の確認を、hx-prompt は入力を求め、入力値を HX-Prompt ヘッダーでサーバーに渡します。

  1. 「入力して送信」を押し、最初の入力ダイアログに短いメッセージを入力します。
  2. 続く確認ダイアログで送信を続けるか選ぶと、サーバーからの応答が結果欄に表示されます。
  3. 確認または入力をキャンセルし、送信されないことを確認します。
  4. 通常フォームでもメッセージと確認欄を使って同じ検証を試します。

空欄・100文字超過・確認なし同上サーバーで入力と確認を検証422・htmx は結果欄、通常フォームはページ全体にエラー
  • hx-prompt の入力値は要求本文ではなく HX-Prompt ヘッダーで送られます。外部 JavaScript はプロンプト値を通常フォームにも保持し、htmx:configRequest で実際のヘッダー値を UTF-8 の URI 表現にします。Controller がデコードし、htmx要求の成功時に通常フォームが送信後に編集されていなければ値を消去します。通信失敗時や応答待ち中に編集した値は通常フォームに残るため、再送できます。hx-params="none" により、他のフォーム値を同時送信しません。
  • hx-prompt の入力は htmx:prompt イベント時に通常フォームへコピーされ、その後に確認ダイアログが表示されます。確認を拒否するとPOSTと結果欄の更新はありませんが、入力した値は通常フォームに残ります。入力ダイアログ自体をキャンセルした場合はフォーム値も結果欄も変わりません。ブラウザー標準ダイアログは表示中に他の画面操作を止めます。
  • 入力値はサーバーで空欄・文字数を検証し、Thymeleaf の th:text でエスケープして表示します。CSRF が有効で、通常フォームも確認欄をサーバーで検証します。
  • 422 は結果欄だけを差し替え、共有 JavaScript がエラーを読み上げ状態にも通知します。その他のHTTPエラー・通信失敗は共通通知に表示します。

異常系と制約

プロンプトは100文字以内の空でない文字列を受け付けます。文字数はJavaの String.length() と同じUTF-16コード単位で数え、100文字の境界は有効です。空欄と101文字以上は422です。通常フォームで送信確認がない場合も422です。値は画面にだけ表示し、保存・他利用者との共有・実際の業務処理はしません。

ブラウザー標準ダイアログの文言・見た目はブラウザーとOSが決めます。高度なレイアウト・非同期操作・アクセシブルなカスタムダイアログが必要な場合は、公式の別例「Dialogs - Custom」等を検討してください。

公式例との差分・出典

htmx 公式 Dialogs の hx-confirm / hx-prompt と HX-Prompt の考え方を使います。日本語対応のため、公式例にはない外部 JavaScript による UTF-8 URI エンコードとサーバー側デコードを加えました。表示するのは架空のメッセージで、出力エスケープ・入力上限・422・CSRF・通常フォーム・日本語解説も追加しています。追加依存はありません。
